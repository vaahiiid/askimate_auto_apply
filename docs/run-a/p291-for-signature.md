**Status: built, not signed.** Nothing here is on `main` as entry content. The batch is the patch
[`p291-for-signature.patch`](./p291-for-signature.patch), applied and signed in one commit, so
`main` never holds an entry no approval covers. An unsigned entry stops his stack and turns CI red
(`loadCatalogueDirectory`, ADR-0055; the pin in `scripts/run-a-profile.test.ts`). Most of the code
the patch needs is on `main` already (P291's commit): the offer, and the two new field properties.
**The parser's fix for the empty string is in the patch itself**, because the fix changes what his signed entry means: his signature covers the entry as parsed, and with the condition's value read, the signed file parses to a different entry (its hash moves from `effa83b5…` to `3b8b6149…`), so on `main` alone his entry would stop loading. The first census on the committed tree caught exactly that, red in `run-a-profile`. It lands
with his signature, which then covers the entry as it will be read.

## Two faults in the code the reads exposed, fixed (the first inside the patch)

- **The empty string read as no value.** The parser dropped a condition's value of `""`, so
  `unlistedDegree`'s recorded rule had no value and could never hold. The box the award title's
  escape opens could never show, and P281's guard on it could never fire. It is the misreading he
  warned about, already in the code. Fixed **in the patch** (`packages/catalogue/src/parse.ts`,
  and a test that is red without the fix), because it moves the hash of the entry he signed.
- **A list's prompt offered as an answer.** The award title's whole list would have shown
  *Select qualification...* among its entries: its value is that text, not `""`. Now a field
  records its `prompt`, and offers never show it.

## Before he signs: his to decide

1. **The award title.** The words are his. Before any page is saved, he can change them by
   asking (ADR-0154), for example *"my award title is DBA, not Doctorate of Business
   Administration"*. That changes the profile for every application. Or he can choose an entry of
   the 41. Nothing here chooses.
2. **The grading system's escape: the proposal he asked for.** Nothing is built.
   - **A (recommended).** Offer the list read after the institution's escape, *GPA 20*, without
     the form's escape. In its place put a plain *"None of these — pass it to a person"*, which
     presses nothing on the form and stops the run for a person. A student is then never led into
     the dead end, and never left without an honest answer. The same *none of these* would let the
     grade be offered after *GPA 20*. That needs a grade list read with the institution escaped,
     because the eight lines sent are not the list.
   - **B.** Offer the escape with a plain sentence saying where it leads: *"choosing it leaves the
     form no way to take your grade, so a person will have to"*. Weaker: it walks a student into a
     dead end knowingly.
3. **The boxes' names in the preview.** Read 1 printed `null` for every unlisted box's label, so
   the entry has no words for them. The offer no longer names them. But the preview the student
   approves would print `unlistedInstitution: HHE` and `unlistedDegree: …`: a developer's handle
   on a student's screen (ADR-0147). A read of the words the page shows beside each box closes it.
   Until then the line is honest but ugly.
